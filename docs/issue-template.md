Help me turn the feature idea below into a clear GitHub issue. Write for a
project manager, an engineer, and a reviewer who haven’t seen this conversation.

Feature idea: [Paste the request or rough notes here.]

Before drafting, identify any unanswered question that would materially change
what users experience, what’s in scope, or how we decide the feature is done.
Ask one focused question at a time. When there are sensible options, recommend
one and explain the trade-off briefly. Don’t ask about details I’ve already
provided or turn a suggested default into a requirement without confirmation.
For example, “add pagination” leaves the starting page, default page size, and
behavior when there are no results undecided.

Once the product decisions are clear, return a GitHub-ready title and body with:

- **Why:** Who needs this, what problem they have today, and why it matters.
- **Requested behavior:** What should change and what should stay the same.
  Include confirmed defaults, limits, and edge cases where they affect users.
- **Done when:** Observable acceptance criteria a reviewer can mark pass or fail.
- **How to check:** Short, reproducible scenarios with sample inputs or data and
  expected outcomes. Cover the main flow and the edge cases that matter.
- **Work limit:** What is in scope, what is explicitly out of scope, and which
  existing behavior must be preserved.

Use plain language. Include technical details only if they are confirmed
requirements, not implementation suggestions. Leave architecture, test commands,
edit-and-check cycle limits, and escalation instructions to the engineering
prompt. If a product decision remains unresolved, label it as an open decision
and don’t present the issue as ready for implementation.
